# handoff

## 次にやるべき1手
- 次の候補は2択に固定する。
- 1) 4コマ統合画像プロンプトの文面（レイアウト指示・吹き出し指示・要約粒度）を最小差分で微調整する
- 2) ここで4コマ構成 + コマ別 + 統合画像プロンプト導線をMVPとして固定し、次テーマへ移る

## 判断基準
- すぐ次テーマへ進みたいなら、現状で一区切りにする
- 実運用で統合プロンプトの指示粒度が不足するなら、`js/engine.js` の統合prompt文面だけ最小追補する
- どちらを選ぶ場合も、既存MVP本体と既存UI導線を壊さないことを優先する

## 今回やらないこと
- 永続化（保存/履歴）
- 外部AI API接続
- Kindle用出力
- 複数画面化や高度なUI演出

## 実装方針
- ルールベースを維持し、Kindle責務は `js/kindle-engine.js` に寄せて拡張する
- 既存MVP本体（`engine.js` / `templates.js`）は触らず、影響範囲を限定する
- UI変更が必要な場合でも、既存導線の追加方式で最小差分にとどめる

## 注意点
- 既存MVP本体（`engine.js` / `templates.js` / 既存3出力導線）は触らない
- Kindle責務は `js/kindle-engine.js` に寄せる
- UI変更は必要最小限を維持し、既存の `chapter-episodes` 再利用方針を崩さない
- 大規模リファクタリングは行わない
- 追加調整する場合も、4コマプロンプト周辺（`buildComicPanelPrompts(...)` / `buildUnifiedComicImagePrompt(...)`）の責務に限定する

# Kindle粒度方針 v1

## 1. このドキュメントの目的
- Kindle原稿化における節本文の標準粒度を正式に固定し、1章（4節）での運用方針を明文化する。
- 量産時にぶれない基準を先に確立し、次フェーズの本文試作を安定させる。

## 2. なぜ今、標準粒度を固定するのか
- `docs/sample-section-drafts.md` で短 / 標準 / 長の比較が完了し、実運用判断に必要な材料が揃ったため。
- 粒度を固定しないまま本文試作へ進むと、節ごとの文字量と読み味が不安定になるため。
- 初回Kindle原稿は速度と再現性を優先する必要があるため。

## 3. 比較に使った前提ドキュメント
- `docs/kindle-drafting-rules-v1.md`
- `docs/sample-section-drafts.md`
- `docs/kindle-chapter-template.md`
- `docs/sample-kindle-chapter-outline.md`

## 4. 短 / 標準 / 長 の比較結果要約
- 短: 読みやすいが背景説明が不足しやすい。
- 標準: 背景説明と実務的な一手のバランスが良く、最も安定。
- 長: 納得感は高いが、作成工数と読者負荷が上がる。

## 5. 現時点で正式採用する粒度
- 正式採用は **標準粒度**。
- 目安文字量: `700〜1000字 / 1節`。

## 6. 採用理由
- 読みやすさと運用負荷のバランスが最も良い。
- 1章4節で構成した際に、章全体の密度が過不足なく揃う。
- note由来の情報を過不足なく残しやすい。

## 7. 採用しない粒度の扱い

### 短をどんな場面で使うか
- 補助節や既知テーマの確認節。
- 章内コラム寄りで、要点提示を優先する場合。
- 1章内で最大1節まで。

### 長をどんな場面で使うか
- 安全系や再発防止など、背景説明が不可欠な節。
- 重点節として掘り下げたい場合。
- 1章内で最大1節まで。

## 8. 1節あたりの基本構成ルール
- 導入フック（4コマ由来）
- 現場で起きたこと
- なぜ起きたか
- 学び
- 次に活かす一手（X要点で締め）

## 9. 1章（4節）あたりの全体バランス方針
- 基本配分: **標準4節** を第一候補とする。
- 例外配分: `標準3 + 短1` または `標準3 + 長1`。
- 短と長を同一章で同時採用するのは初版運用では避ける。

## 10. 節ごとに粒度を変えてよい条件
- 章全体の問いに対して、説明深度を変える合理的理由がある。
- 変更後も章全体の読み味（テンポ）が崩れない。
- 変更理由を章設計メモに明記できる。

## 11. 読みやすさと運用負荷のバランス基準
- 読みやすさ: 1段落1主題、節末で学びが回収される。
- 運用負荷: 節1本あたりの編集時間が過度に増えない。
- 判断軸: 迷った場合は標準粒度を優先する。

## 12. 初回 Kindle 原稿で推奨する配分案
- 推奨配分A: `標準4`（最優先）
- 推奨配分B: `標準3 + 短1`（確認節がある場合）
- 推奨配分C: `標準3 + 長1`（重点節が必要な場合）

## 13. 今後の原稿生成ルールへどう接続するか
- 粒度をメタ情報として扱う（sectionLength: short/standard/long）。
- 自動生成時は標準をデフォルト設定にする。
- 例外粒度（短/長）は章ごとの上限ルールを適用する。

## 14. 今はまだ固定しないこと
- 章全体の厳密文字数上限（媒体仕様次第）。
- 著者別の文体差プリセット。
- 章テーマ別の粒度自動提案ロジック。

## 15. 次フェーズで試すべきこと
- 1章分（4節）を標準粒度で試作し、総文字量と読了感を確認する。
- 必要なら `標準3 + 短1` を比較し、章テンポの差を記録する。
- 将来のKindle原稿生成ルール向けに、粒度メタ情報の最小項目を定義する。

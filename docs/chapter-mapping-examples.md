# Chapter Mapping 試作例

## 1. このドキュメントの目的
- `docs/kindle-bridge-design.md` の設計仮説が、代表ケースで無理なく運用できるかを確認する。
- 実装前に「1エピソード -> 1節」「3〜4節 -> 1章」の妥当性を、具体例で検証する。

## 2. 使用する代表ケース（3〜5件）
- `TC-02`（荷上げ時のヒヤリ）
- `TC-03`（段取り見直しで時短）
- `TC-05`（搬入導線の見直し）
- `TC-06`（日報の読み合わせ）

## 3. なぜそのケースを選んだか
- 安全系（`TC-02` `TC-05`）と改善系（`TC-03` `TC-06`）を混ぜ、章内の温度差を検証できるため。
- patternが `ヒヤリ型` と `気づき型` にまたがり、節の並び替えの耐性を確認できるため。
- 直近でX長文を調整したケース（`TC-03` `TC-06`）を含み、章リード素材として使えるか確認しやすいため。

## 4. 1エピソード -> 1節 の試作
- 節A（`TC-02`）  
  - 節タイトル候補: 「ヒヤリの一瞬を止める合図設計」  
  - 本文主軸: note（原因 -> 再発防止）  
  - コラム候補: 4コマ（緊張 -> 停止 -> 再確認 -> 学び）
- 節B（`TC-03`）  
  - 節タイトル候補: 「小さな段取り改善が時短を生む」  
  - 本文主軸: note（改善の背景 -> 学び）  
  - コラム候補: 4コマ（気づきの流れ）
- 節C（`TC-05`）  
  - 節タイトル候補: 「搬入導線は先に共有して詰まりを防ぐ」  
  - 本文主軸: note（干渉発生 -> 予防策）  
  - コラム候補: 4コマ（close-call文脈）
- 節D（`TC-06`）  
  - 節タイトル候補: 「朝5分の読み合わせで予兆を拾う」  
  - 本文主軸: note（振り返り -> 実務接続）  
  - コラム候補: 4コマ（awareness文脈）

## 5. 複数エピソード -> 1章 の試作
- 章タイトル候補: 「AI武装親方｜現場のズレを小さくする段取り術」
- 章リード候補: `TC-03` と `TC-06` のX長文を統合し、「改善は小さく回す」を冒頭で提示。
- 節構成（4節 / 1章）
  1. ヒヤリを止める手順（`TC-02`）
  2. 導線干渉を防ぐ共有（`TC-05`）
  3. 工具配置の小改善（`TC-03`）
  4. 日報読み合わせの再利用（`TC-06`）
- 章まとめ候補
  - 共通学び1: 「先に共有するとズレは小さくなる」
  - 共通学び2: 「振り返りを次工程に接続すると再発が減る」
  - 共通学び3: 「小さな改善を標準化すると余裕が生まれる」

## 6. 4コマ / note / X を章素材へどう割り当てるか
- 4コマ: 各節冒頭の導入フック、または章内コラム枠。
- note: 各節本文の主素材（最小編集で利用）。
- X:
  - 短文版: 節タイトル候補の種
  - 長文版: 章リード候補
  - ハッシュタグ案: 章末の訴求キーワード候補

## 7. 章タイトル候補
- AI武装親方｜現場のズレを小さくする段取り術
- AI武装親方｜ヒヤリと手戻りを減らす現場改善メモ
- AI武装親方｜小さな改善を標準化する現場実践録

## 8. 節タイトル候補
- ヒヤリの一瞬を止める合図設計
- 搬入導線の共有で詰まりを防ぐ
- 工具配置の見直しで流れを整える
- 朝の読み合わせで予兆を先回りする

## 9. 実際にやってみて分かったこと
- `1エピソード = 1節` は現行note構造と相性がよく、見出し調整だけで節化できる。
- 4コマは本文よりも「節の掴み」として置く方が自然。
- X長文は章リードに使いやすいが、章トーンに合わせた1回の再編集は必要。

## 10. 現時点の推奨粒度
- 第一候補: `1エピソード = 1節`、`3〜4節 = 1章`
- 理由: 現行の生成粒度を崩さず、章化時の再編集負荷が最小なため。

## 11. 次フェーズへ持ち越す課題
- 章リードの統合ルール（複数X長文をどう1段落にまとめるか）
- 章末まとめの統合ルール（学び重複の圧縮方法）
- 章マッピング時の並び順ルール（安全系 -> 改善系など）

# 出力評価ガイド

## 目的
- 出力品質の調整を感覚ではなく、同一ケース比較で進めるための基準を定義する。
- `samples/test-cases.js` を固定ベンチマークとして、改善前後の差分を確認する。

## 何を評価するか
- 4コマ / note / X の3出力で、同じ学びが一貫しているか。
- トーン（ゆるい / 少し真面目 / かなり真面目 / コミカル）の文体差が出ているか。
- コパイロットの役割（質問役・疑問代弁）が崩れていないか。
- 入力不足（短文・空欄寄り）でも破綻しないか。
- 4コマが必ず「小さな学び」で終わるか。

## 代表ケースの見方
- `expectedPattern` は期待する4コマ型。
  - `misunderstanding`: 誤解型
  - `closeCall`: ヒヤリ型
  - `awareness`: 気づき型
- `expectedLearningFocus` は、3出力すべてで回収したい学びの要点。
- まず `TC-01` から `TC-08` を通しで確認し、次に崩れたケースだけ再確認する。

## 合格基準
- 8ケース中、最低7ケースで `expectedPattern` と実出力の意図が一致する。
- 全ケースで、4コマ4コマ目に学びが明示される。
- 全ケースで、noteとXが4コマの学びから大きく逸脱しない。
- 4トーンすべてで、語り口または温度感の差が目視で判別できる。
- 空欄・短文ケース（最低2件）でも空欄表示や意味破綻がない。

## よくある崩れ方
- 4コマは成立しているが、noteで別テーマに飛ぶ。
- X短文が要約ではなく断片になり、学びが消える。
- かなり真面目トーンでも、ゆるい語尾が混ざる。
- 入力不足時に同じ定型文ばかりで、ケース差がなくなる。
- コパイロットが単なる相槌のみで、質問役の機能が弱まる。

## 次回以降の調整ルール
- 調整は `templates.js` 優先、`engine.js` は分岐や補完の最小変更にとどめる。
- 変更ごとに全ケースを再確認し、崩れたケースIDを記録する。
- 新しい崩れ方が出たら、まず `samples/test-cases.js` に再現ケースを追加してから修正する。
- UIや入力項目は増やさず、出力品質改善に集中する。

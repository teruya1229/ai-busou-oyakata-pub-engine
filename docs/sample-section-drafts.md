# 1節分サンプル本文（短 / 標準 / 長）

## 1. このドキュメントの目的
- `docs/kindle-drafting-rules-v1.md` の粒度定義（短 / 標準 / 長）が、同一エピソードで実運用可能かを確認する。
- 完成原稿ではなく、量産時に使える本文粒度を比較検証する。

## 2. 使用する代表ケース
- `TC-06`（日報の読み合わせ）

## 3. なぜそのケースを選んだか
- 気づき型で、導入フック・背景説明・実務接続を自然に展開しやすいため。
- 安全系ほど緊急語が多くなく、短 / 標準 / 長の差を比較しやすいため。
- 既存ドキュメントで章素材として複数回使っており、比較軸を揃えやすいため。

## 4. 節タイトル案
- 朝5分の読み合わせで予兆を先回りする

## 5. この節で伝えたい学び
- 過去ログは「記録」で終わらせず、朝の短い確認で次工程に接続すると効果が出る。

## 6. 4コマ / note / X をどう素材として使うか
- 4コマ: 導入フック（読み合わせで予兆に気づく場面）に利用。
- note: 本文骨格（起きたこと -> なぜ -> 学び）に利用。
- X: 節末の要点一文と小見出し補助に利用。

## 7. 短バージョン本文
朝の打ち合わせ前、照屋親方とコパイロットは昨日の日報を5分だけ読み返した。すると、前日に小さく見えた違和感が、今日の作業順でも再発しそうだと分かった。  

問題は、現場で感じた気づきが「記録しただけ」で止まり、次の手順に反映されていなかったことだ。読み合わせを入れるだけで、事前に確認すべき順番が明確になる。  

学びはシンプルだ。過去ログは朝の5分で効く。短い確認を先に置くことで、同じつまずきを減らせる。

## 8. 標準バージョン本文
朝礼前、照屋親方はコパイロットと一緒に前日の日報を読み合わせた。現場では「もう済んだ話」に見えていた小さな違和感が、今日の作業でも同じ形で出る可能性があると分かった。読み合わせは短時間でも、当日の段取りを整える入口になる。  

なぜ効果が出るかというと、記録を行動に変える手順が生まれるからだ。日報そのものは情報の置き場にすぎないが、朝に読み返して「今日どこを先に見るか」を決めると、注意点が具体的なチェック項目へ変わる。結果として、現場の認識差が小さくなる。  

この節で押さえたいのは、振り返りを過去の整理で終わらせないことだ。朝5分でよいので、前日の記録を次工程の確認項目へ接続する。  

要点は明確だ。過去ログは朝の5分で効く。短い再確認を習慣化すると、予兆の段階で手戻りを止めやすくなる。

## 9. 長バージョン本文
朝の現場は、作業開始前の数分でその日の流れが決まる。照屋親方は、朝礼の前にコパイロットと前日の日報を読み合わせる習慣を続けている。今回も、作業メモの中に残っていた小さな違和感を拾ったことで、同じミスの予兆に早く気づけた。前日には問題化しなかった情報でも、翌日の段取りに当て直すと意味が変わる。  

現場で起きる再発の多くは、情報不足より接続不足に近い。記録は残っているのに、今日の判断に使う手順がないため、同じ注意点をまた見落とす。日報を読み合わせる行為には、情報を再利用する順番を作る役割がある。  

具体的には、前日の記録から「今日の最初に確認する点」を2つ程度に絞る。次に、その確認点を班内で一文共有する。これだけで、曖昧な注意喚起が実際の行動に変わる。読み合わせを長くする必要はない。むしろ短く、毎日続けられる形にする方が効く。  

このやり方の利点は、ヒヤリや手戻りの芽を作業前に拾えることだ。現場に入ってから気づくと調整コストが大きくなるが、朝の段階なら順番変更や役割分担の見直しで吸収しやすい。  

結論として、過去ログは「ためる資産」ではなく「朝に使う道具」として扱うべきだ。過去ログは朝の5分で効く。振り返りを次の実務に接続する仕組みを先に作れば、再発防止は特別な仕組みなしでも前進する。

## 10. 3パターンを比較して分かったこと
- 短は即読性が高いが、背景説明が薄くなりやすい。
- 標準は背景と実務手順のバランスが良く、量産運用に向く。
- 長は説得力が高いが、1章内で多用すると読み疲れが出やすい。

## 11. 読み味の比較
- 短: 要点先行でテンポが良い。
- 標準: 問題->理由->行動の流れが自然で最も読みやすい。
- 長: 現場感と納得感は高いが、集中力が必要。

## 12. 運用負荷の比較
- 短: 低（編集時間が短い）
- 標準: 中（最低限の構成調整が必要）
- 長: 高（段落設計と重複整理の工数が増える）

## 13. 現時点の推奨粒度
- 推奨は「標準」。
- 理由: 読みやすさと運用負荷のバランスが最も良く、1章4節運用にも適合するため。

## 14. 今後の原稿化ルールへどう反映するか
- `docs/kindle-drafting-rules-v1.md` の「標準を第一推奨」を維持する。
- 長は1章1節まで、短は補助節に限定する運用ルールを明記する。
- 節末要点はX短文由来の一文で統一する。

## 15. 次フェーズへ持ち越す課題
- 別ケース（安全系）でも同じ粒度比較を行い、標準粒度の妥当性を再確認する。
- 1章4節を実際に並べたときの総文字量レンジを確定する。
- 将来の自動原稿生成に向け、粒度別テンプレの入力項目を最小化する。

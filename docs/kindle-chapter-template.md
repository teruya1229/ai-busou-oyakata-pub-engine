# Kindle章テンプレ固定ルール

## 1. このドキュメントの目的
- Kindle前段設計で検証した内容を、運用可能な「章粒度と章テンプレの固定ルール」として明文化する。
- 実装前に仕様を固定し、MVP本体を崩さず次フェーズへ渡す基準にする。

## 2. 現時点で固定する章粒度
- 固定粒度は以下とする。
  - `1エピソード = 1節`
  - `3〜4節 = 1章`

## 3. なぜその粒度にするのか
- 現行出力（4コマ / note / X）が1入力1エピソードで成立しており、節化が最小編集で可能。
- 3〜4節で1章にすると、章としての読み応えと編集コストのバランスが良い。
- 過度な自動整形を避け、まずは章素材を安定供給する方針に合致する。

## 4. 1エピソード = 1節 の定義
- 入力1件（現場メモ1件）を1エピソードと定義する。
- 1節は、原則として以下素材を持つ。
  - 節タイトル（X短文またはnote見出し由来）
  - 節導入フック（4コマ要約）
  - 節本文（note本文）
  - 節要点（X短文/長文の要約）

## 5. 3〜4節 = 1章 の定義
- 同一テーマ群の節を3〜4本束ねて1章とする。
- 章は、導入・展開・応用・まとめの流れを基本とする。
- 章末に共通学びを2〜3点で統合する。

## 6. Kindle章の標準テンプレ
- 章タイトル
- 章リード（X長文ベース）
- 節1（エピソードA）
- 節2（エピソードB）
- 節3（エピソードC）
- 節4（任意、エピソードD）
- 章内コラム（4コマ抜粋、任意）
- 章まとめ（共通学び）

## 7. Kindle節の標準テンプレ
- 節タイトル
- 導入フック（4コマ1〜2行要約）
- 現場で起きたこと（note）
- なぜ起きたか（note）
- 学び（note）
- 次に活かす一手（X短文/長文から再編集）

## 8. 4コマ / note / X の役割固定
- 4コマ: 節の導入フック、または章内コラム。
- note: 節本文の主素材（原文ベースで利用）。
- X:
  - 短文版: 節タイトル候補 / 要点抽出
  - 長文版: 章リード候補 / 帯文候補
  - ハッシュタグ案: 章末キーワード整理の補助

## 9. 現行出力から章素材へ変換する実務ルール
- ルール1: 1入力ごとに「節素材セット」を先に確定する。
- ルール2: 節本文はnoteを優先し、改稿は見出し調整と接続文の補足に限定する。
- ルール3: 4コマは本文化せず、導入フックまたはコラムで使う。
- ルール4: X長文は章リード化する際、1〜2文へ圧縮する。
- ルール5: 章まとめは各節の学び行を重複除去して統合する。

## 10. 章タイトルの付け方
- 第一候補: X短文の冒頭キーワード + テーマ名。
- 第二候補: 共通学びを要約した文。
- 命名基準:
  - 現場語を1語以上含む
  - 効果（防ぐ/減らす/整える）を含む
  - 25〜40字程度に収める

## 11. 節タイトルの付け方
- 原則は「課題 + 行動 + 期待効果」の3要素で構成する。
- 例:
  - 「搬入導線の共有で詰まりを防ぐ」
  - 「朝5分の読み合わせで予兆を先回りする」
- 1節ごとに重複語が続く場合は、行動語を変えて読みやすさを確保する。

## 12. 将来の自動原稿生成で差し込むべきポイント
- 節素材セットのメタ情報（episodeId / themeGroup / tone / pattern）。
- 章候補自動束ね（3〜4節）の並び順ルール。
- 章リード自動圧縮ルール（X長文 -> 章導入文）。
- 章まとめ自動統合ルール（学び重複除去）。

## 13. 今はまだ固定しないもの
- Kindle本文の自動生成ロジック本体。
- EPUB出力・自動組版。
- 章ごとの文字数最適化アルゴリズム。
- 外部API連携や保存機能の実装。

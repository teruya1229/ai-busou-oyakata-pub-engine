# Kindle原稿化ルール v1

## 1. このドキュメントの目的
- `docs/sample-kindle-chapter-outline.md` の試作を実運用へつなぐため、原稿化時の書き方ルールを初版として固定する。
- 実装前に文章運用ルールを先に定義し、MVP本体を変更せず次フェーズを進める基準にする。

## 2. なぜ今「原稿化ルール初版」を作るのか
- 章粒度と章テンプレは固定できたため、次は本文化の一貫ルールが必要な段階だから。
- ルールなしで原稿化を始めると、章ごとの文体・長さ・構成がぶれやすいため。
- 将来の自動原稿生成へ接続する前に、人手運用で破綻しない最小基準を確立するため。

## 3. 前提として使う既存ドキュメント
- `docs/kindle-bridge-design.md`
- `docs/chapter-mapping-examples.md`
- `docs/kindle-chapter-template.md`

## 4. 節ごとの文章粒度の定義

### 短
- 目安: 350〜550字
- 構成: 導入1段落 + 本文1段落 + 学び1段落
- 用途: 補助節、既知テーマの確認節

### 標準
- 目安: 700〜1000字
- 構成: 導入1段落 + 背景/原因2段落 + 学び1段落 + 次の一手1段落
- 段落数目安: 5段落前後（最大6段落）
- 用途: 章の中心となる通常節（第一推奨）

### 長
- 目安: 1100〜1500字
- 構成: 導入1段落 + 具体事例2〜3段落 + 学び2段落 + 応用1段落
- 用途: 章内で重点化したい節（1章につき最大1節）

## 5. 各粒度の想定用途
- 短: 章内コラム寄り、補足の位置づけ。
- 標準: 基本運用。まずは全節を標準で作り、必要時のみ短/長へ調整。
- 長: 安全系や再発防止系など、背景説明が必要なケースに限定。

## 6. Kindle原稿における基本の文体ルール
- 主語と述語を近づけ、1文を長くしすぎない。
- 現場語は残すが、初出時に短い補足を入れる。
- 断定しすぎず、再現可能な行動表現で締める。
- 口語寄りすぎず、実務者が読み返しやすい文体を優先する。

## 7. 章の書き方ルール
- 章導入で「この章の問い」を1つ提示する。
- 4節は「問題認識 -> 防止 -> 改善 -> 定着」の順を基本に並べる。
- 章末まとめは3点以内に絞り、次章への接続文を1文添える。

## 8. 節の書き方ルール
- 節冒頭に導入フック（4コマ由来）を置く。
- 中盤で「なぜ起きたか」を必ず明文化する。
- 終盤で「次に活かす一手」を具体動詞で示す。
- 節末はX短文由来の一文で要点を回収する。
- 1節の文章まとまりは「4〜6段落」「1段落2〜4文」を基本にし、長文化しすぎる段落は分割する。
- 節末要点は1文のみとし、本文の主学びを言い換えて回収する（新情報を足しすぎない）。
- 節末要点の文末は「〜する。」の行動断定で統一し、「〜である。」と混在させない。

## 9. 4コマをどう文章導入へ変換するか
- 4コマの1〜2コマ目を、導入段落の「状況説明」に転換する。
- 3コマ目の気づきを、導入末尾の問題提起文へ変換する。
- 4コマ目の学びは導入に重複させず、節終盤で回収する。
- 導入の書き出しは毎節で固定しない（状況起点 / 判断起点 / 違和感起点を回す）。
- 同型化回避のため、導入1文目で使う語を連続させない（例: 「現場では」「今回のケースでは」の連続を避ける）。

## 10. note本文をどう主本文へ変換するか
- noteの見出し順（現場で起きたこと -> なぜ -> 学び）を基本維持する。
- 冗長な言い回しのみ削り、事実と学びの対応関係は崩さない。
- 章文脈に合わせて接続文を追加し、単独記事感を弱める。

## 11. X投稿文をどう要点・見出しへ変換するか
- X短文: 節タイトル候補と節末要点に使用。
- X長文: 章導入リードまたは節冒頭補助文に使用。
- ハッシュタグ案: 章末キーワード抽出の補助に限定し、本文へ直接挿入しない。
- X由来の文量は1節全体の2割以内を目安にし、本文の主軸（note由来）を上書きしない。
- X由来要点を本文へ入れる場合は、1節につき「節末要点1文 + 補助1文まで」を上限にする。

## 12. 章末まとめの書き方
- 各節の「学び」を横断して、重複しない3点に統合する。
- 形式は「行動 + 効果」の形で統一する。
- 最後に「次章で何を扱うか」を1文で示す。

## 13. 読みやすさの判断基準
- 1段落1主題が守られている。
- 専門語が連続しすぎず、読み返しなしで理解できる。
- 節の冒頭と末尾で同じ学びを回収できる。
- 実務者視点で「明日試せる一手」が最低1つ示される。
- 標準粒度で同義反復が2回以上出る場合は削る（冗長化の早期サイン）。
- 接続語が連続する文（例: しかし、また、さらに）は1段落1回までを目安にする。

## 14. 今はまだ固定しないこと
- 章ごとの厳密文字数上限（媒体仕様依存のため保留）。
- 語尾バリエーションの細かな最適化。
- 著者別文体プリセット。
- 自動要約や自動章並べ替えロジック。

## 15. 次フェーズで実際に試すべきこと
- 1節分サンプル本文を「短/標準/長」で各1本ずつ試作する。
- 同一エピソードで粒度差を比較し、読みやすさ評価を記録する。
- 1章分（4節）を仮組みし、章導入と章末まとめの接続感を確認する。

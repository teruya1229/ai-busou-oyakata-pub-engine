# 1章分の実例原稿構成（試作）

## 1. このドキュメントの目的
- `docs/kindle-chapter-template.md` の固定ルールに沿って、1章分の原稿構成が自然に流れるかを検証する。
- 完成原稿ではなく、実務運用できる「章構成の下書き粒度」を確認する。

## 2. どの代表ケースを使って1章を構成するか
- `TC-02`（荷上げ時のヒヤリ）
- `TC-05`（搬入導線の見直し）
- `TC-03`（段取り見直しで時短）
- `TC-06`（日報の読み合わせ）

## 3. なぜそのケースを選んだか
- 安全系（`TC-02` `TC-05`）と改善系（`TC-03` `TC-06`）を1章に収めることで、現場の実務的な流れを再現しやすい。
- 4節構成に必要な最低数を満たし、`1エピソード = 1節` の運用検証が可能。
- 既存chapter mapping試作と整合し、比較しやすい。

## 4. 章タイトル案
- AI武装親方｜ズレを小さくする現場段取り術
- AI武装親方｜ヒヤリと手戻りを減らす4つの実践
- AI武装親方｜安全と時短を両立する現場改善メモ

## 5. この章で伝えたい中心メッセージ
- 「先に共有し、短く振り返る」だけで、ヒヤリと手戻りは確実に減らせる。

## 6. 章全体の流れ（導入 -> 4節 -> まとめ）
- 導入: 現場のズレは偶発ではなく、共有不足と振り返り不足で増幅する。
- 第1節: ヒヤリを止める（`TC-02`）
- 第2節: 導線干渉を防ぐ（`TC-05`）
- 第3節: 小改善を標準化する（`TC-03`）
- 第4節: 振り返りを次工程へ接続する（`TC-06`）
- まとめ: 共通ルールを3点に統合し、次章へ接続。

## 7. 第1節の構成
- 節タイトル案: ヒヤリの一瞬を止める合図設計
- 導入フック（4コマ要約）: 声かけの遅れがヒヤリを生み、停止と再確認で流れを戻す。
- 本文主軸（note）: ヒヤリ発生 -> 要因整理 -> 再発防止手順。
- 要点（X）: 「危険時は作業を止め、合図を統一する。」

## 8. 第2節の構成
- 節タイトル案: 搬入導線の共有で詰まりを防ぐ
- 導入フック（4コマ要約）: 導線干渉で詰まりが発生しかけ、事前共有で回避。
- 本文主軸（note）: 干渉の発生条件 -> 共有方法 -> 予防策。
- 要点（X）: 「ルート図を先に共有して干渉を避ける。」

## 9. 第3節の構成
- 節タイトル案: 工具配置の見直しで流れを整える
- 導入フック（4コマ要約）: 小さな配置変更が作業の連続性を改善。
- 本文主軸（note）: 改善前後の差 -> 継続運用のコツ。
- 要点（X）: 「小さな改善を現場標準にする。」

## 10. 第4節の構成
- 節タイトル案: 朝の読み合わせで予兆を先回りする
- 導入フック（4コマ要約）: 昨日の記録を読むことで同種トラブルを未然回避。
- 本文主軸（note）: 振り返り手順 -> 実務接続。
- 要点（X）: 「過去ログは朝の5分で効く。」

## 11. 各節で 4コマ / note / X をどう使うか
- 4コマ: 各節冒頭の導入フック（1〜2行）として使用。
- note: 各節本文の骨格として使用（見出し調整のみ）。
- X:
  - 短文版: 節要点・小見出し候補
  - 長文版: 導入段落の補助文
  - ハッシュタグ案: 章末キーワード抽出補助

## 12. 章末まとめの案
- まとめ1: 危険や詰まりは、先に「止める基準」を共有すると抑えやすい。
- まとめ2: 小さな改善は、標準化してはじめて再現性を持つ。
- まとめ3: 朝5分の振り返りが、次工程のミス予防に直結する。

## 13. Kindle原稿化したときの読み味メモ
- 実務寄りで読みやすく、現場経験者がすぐ使える手順に落とし込みやすい。
- 4コマフックが先に入ることで、節本文の理解導線が短くなる。
- X要点を節末に添えると、読後の記憶に残りやすい。

## 14. この試作で分かったこと
- `1エピソード = 1節` は現行出力の粒度と整合し、編集負荷が低い。
- `4節 = 1章` は安全系と改善系のバランスを取りやすい。
- 章化では、X長文を「章導入補助」に限定する運用が安定する。

## 15. 次フェーズへ持ち越す課題
- 節ごとの本文文字量の目安（短/標準/長）を決める。
- 章タイトル決定ルール（候補からの採択基準）を明文化する。
- 将来のKindle原稿生成ルールに接続するため、章素材メタ情報の定義を整理する。
